# First Client Onboarding - Lensys Care

Este documento descreve o roteiro de validação assistida do primeiro cliente real do Lensys Care. O objetivo é validar o uso em ambiente real, identificar fricções cedo e observar estabilidade antes de ampliar o acesso.

## 1. Objetivo do onboarding

- Validar o uso real do Lensys Care com o primeiro cliente.
- Identificar dificuldades antes de escalar para outros usuários.
- Acompanhar performance, clareza de fluxo e estabilidade.

## 2. Antes de começar

Checklist:

- conta criada.
- plano definido.
- nome da clínica configurado.
- nome/preferred_name configurado.
- login funcionando.
- cliente sabe acessar o link correto.
- cliente sabe que o sistema ainda está em fase de validação assistida.

## 3. Fluxo principal do primeiro uso

Checklist:

- acessar o sistema.
- fazer login.
- abrir dashboard.
- cadastrar primeiro paciente.
- abrir ficha do paciente.
- lançar novo exame.
- preencher graduação refrativa.
- preencher adição/DP/observações, se aplicável.
- finalizar e registrar exame.
- abrir histórico.
- imprimir receita.
- voltar para pacientes.
- localizar paciente pela busca.

## 4. Fluxo de pacientes

Checklist:

- cadastrar paciente.
- buscar paciente.
- ordenar por mais recentes.
- abrir ficha.
- editar paciente.
- tentar excluir paciente sem exame.
- confirmar bloqueio em paciente com exame/histórico.

## 5. Fluxo de exames

Checklist:

- criar exame.
- editar exame.
- imprimir receita.
- usar exame anterior como base, quando houver.
- conferir data da consulta.
- conferir acuidade visual.
- conferir observações da receita.

## 6. Fluxo de alertas/recalls

Checklist:

- abrir alertas.
- filtrar por status.
- ordenar por vencimento.
- entender pendentes/enviados/cancelados.
- testar recall manual apenas se for seguro.
- confirmar se os textos são claros para o usuário.

## 7. Minha Conta e Assinatura

Checklist:

- abrir `/account`.
- editar nome/preferred_name.
- confirmar atualização na sidebar.
- abrir `/subscription`.
- conferir plano atual.
- entender diferença entre a página pública `/planos` e a página interna `/subscription`.

## 8. Mobile/tablet

Checklist:

- abrir no celular.
- testar menu lateral.
- cadastrar paciente.
- abrir ficha.
- criar exame simples.
- abrir receita/impressão.
- observar se algum botão fica difícil de clicar.

## 9. O que observar durante o uso real

- lentidão perceptível.
- dificuldade para encontrar paciente recém-cadastrado.
- dúvida no formulário de exame.
- dúvida em alertas/recalls.
- problema ao imprimir.
- textos confusos.
- necessidade de recepcionista/equipe.
- campos faltantes no cadastro.
- fluxo que exige cliques demais.

## 10. Limitações conhecidas

- gestão de equipe/recepcionista ainda é futura.
- alteração de e-mail/senha ainda é futura.
- arquivamento de paciente ainda é futuro.
- WhatsApp/SMS podem estar em validação.
- agenda/calendário ainda é futuro.
- campanhas/tráfego pago é feature premium futura.

## 11. Perguntas para fazer ao cliente

- O cadastro de paciente ficou claro?
- Você conseguiu encontrar o paciente depois?
- O exame tem todos os campos necessários?
- A receita impressa ficou adequada?
- A tela ficou rápida o suficiente?
- O sistema funcionou bem no celular/tablet?
- O que te confundiu?
- O que você esperava encontrar e não encontrou?

## 12. Critérios de sucesso da primeira validação

- cliente consegue logar sem ajuda.
- cliente cadastra paciente sem ajuda.
- cliente cria exame sem ajuda.
- cliente imprime receita.
- cliente encontra paciente depois.
- cliente entende alertas básicos.
- nenhuma lentidão bloqueante.
- nenhum bug crítico em fluxo clínico.

## 13. Próximas melhorias prováveis após validação

- equipe/recepcionista.
- permissões por papel.
- agenda.
- arquivamento de paciente.
- melhoria de impressão.
- relatórios simples.
- performance com mais dados.
- automações de recall.
